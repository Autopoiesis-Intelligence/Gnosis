## Evidence and change discipline

AI context is disposable; repository state and reproducible evidence are persistent. Never treat a previous chat, stale commit, old CI result, README statement or generated summary as proof of the current repository state.

Use the evidence ladder:

DESIGN → IMPLEMENTED → REACHABLE → RUNTIME → PERSISTED → AUDITED → CI_PROVEN.

Do not promote a claim without the evidence required for its status. A test pass does not prove runtime behavior; repository visibility does not grant authority; persistence does not prove ingestion or execution; approval is not execution; a receipt is not execution proof.

When a historical identifier must remain in provenance, do not silently rewrite it: add a current canonical mapping while preserving the exact historical source identity.
