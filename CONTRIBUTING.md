# Contributing to Gnosis

## Start with the evidence

1. Read the [project README](README.md) and current issue discussion.
2. Describe the problem or proposed outcome before making broad changes.
3. Reference exact files, commit SHAs, test commands, and CI runs when available.
4. Keep changes small and reviewable; prefer a pull request over direct edits to protected branches.
5. Do not describe a capability as implemented without source and relevant verification evidence.

## Safety and privacy

Never commit credentials, signing keys, access tokens, private partner data, or personal information. Generated documentation is a proposal until checked against current source and evidence.

## Feedback

Use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md) or [feature request template](.github/ISSUE_TEMPLATE/feature_request.md).
